Репозиторий с практическим заданием № 2 по дисциплине "Конфигурационное управление", студента группы ИКБО-23-25 Кузнецов С.

## Практическая работа №2. Вариант 11

Инструмент анализа зависимостей Python-пакетов.

### Этап 1. Минимальный прототип

Реализовано CLI-приложение с аргументами:

- `--package` — имя анализируемого пакета (обязательный).
- `--repository` — URL репозитория или путь к тестовому файлу
  (обязательный).
- `--test-mode` — использовать локальный тестовый репозиторий.
- `--ascii-tree` — включить режим ASCII-дерева.

В первом этапе приложение выводит значения параметров.
Реализована проверка имени пакета, URL и тестового файла.

### Запуск

```bash
python src/main.py --package requests --repository https://pypi.org/pypi
```

На Windows также можно использовать:

```bat
run.bat --package requests --repository https://pypi.org/pypi
```

### Запуск тестов

```bash
python -m unittest discover -s tests -v
```

### Тестовый режим

```bash
python src/main.py --package A --repository tests/graph.txt --test-mode
```

### Требования

Python 3.10 или новее. Сторонние библиотеки не используются.

## Этап 2. Сбор данных

Реализовано получение прямых зависимостей Python-пакетов
из репозитория PyPI через JSON API.

Для получения данных используются стандартные библиотеки
Python: `urllib` и `json`. Менеджер пакетов pip и сторонние
библиотеки для получения зависимостей не используются.

### Основные функции

- `fetch_package_metadata()` — получает JSON-метаданные пакета
  с помощью HTTP-запроса.
- `get_direct_dependencies()` — извлекает записи прямых
  зависимостей из поля `requires_dist`.
- `show_dependencies()` — выводит найденные зависимости.

### Пример запуска

```bash
python -m src.main --package requests --repository https://pypi.org/pypi
```

Программа выводит список объявленных прямых зависимостей
пакета с ограничениями версий и условиями установки.

### Обработка ошибок

Предусмотрена обработка:
- отсутствующего пакета (HTTP 404);
- других ошибок HTTP;
- ошибок подключения к репозиторию;
- некорректных аргументов командной строки.

### Ограничения текущей реализации

Поддерживается JSON API PyPI. Произвольные репозитории,
не предоставляющие совместимый API, не поддерживаются.

Зависимости с маркерами `extra` пока выводятся вместе
с остальными записями. Обход транзитивных зависимостей
будет реализован на третьем этапе.

## Этап 3. Рекурсивное построение графа зависимостей

Реализовано построение графа зависимостей Python-пакетов
с использованием рекурсивного обхода DFS.

### Возможности

- Получение транзитивных зависимостей из PyPI.
- Рекурсивное построение графа зависимостей.
- Обнаружение циклических зависимостей.
- Предотвращение повторной обработки пакетов.
- Работа с локальным тестовым графом.

### Запуск с PyPI

```bash
python -m src.main --package requests --repository https://pypi.org/pypi
```

### Тестовый режим

```bash
python -m src.main --package A --repository tests/graph.txt --test-mode
```

### Ограничения реализации

- Поддерживается JSON API PyPI.
- Условные зависимости с маркером `;` пропускаются.
- Максимальное количество пакетов в графе — 50.
- ASCII-дерево и порядок загрузки будут реализованы
  на следующих этапах.

### Тестирование

```bash
python -m unittest discover -s tests -v
```

## Этап 4. Порядок загрузки зависимостей

Реализован алгоритм топологической сортировки графа
зависимостей с использованием рекурсивного DFS.

Каждый пакет добавляется в результат после обработки
всех его зависимостей.

### Запуск с тестовым графом

```bash
python -m src.main --package A --repository tests/graph.txt --test-mode
```

Для тестового графа получен порядок:

```text
D -> B -> C -> A
```

### Запуск с PyPI

```bash
python -m src.main --package requests --repository https://pypi.org/pypi
```

### Сравнение с pip

Для сравнения использовалась команда:

```bash
python -m pip install --dry-run --ignore-installed requests
```

При проверке обнаружены одинаковые пакеты:

- requests
- charset_normalizer
- idna
- urllib3
- certifi

Наш алгоритм формирует топологический порядок,
при котором зависимости предшествуют пакету.

Вывод pip содержит выбранные версии дистрибутивов.
Порядок перечисления в строке Would install нельзя
считать гарантированным порядком установки.

Наш анализатор не выполняет разрешение версий,
не учитывает все маркеры окружения и пропускает
условные зависимости с символом `;`.

### Обработка циклов

При обнаружении циклической зависимости алгоритм
вызывает ValueError с указанием последовательности
пакетов, образующих цикл.
